## 🧱 Как работает GitHub Pages, и что он умеет из коробки

GitHub Pages хостит только **статические файлы** (HTML/CSS/JS) — у него нет серверной части (PHP/Python/Node не запускается на хостинге), нет встроенной базы данных.

Но для сайта с гайдами и билдами это **не проблема**, потому что:
- 99% фич которые нам нужны работают на клиенте в браузере
- Всё что нужно "от сервера" можно получить через бесплатные внешние API и сервисы
- Контент хранится в виде простых Markdown файлов прямо в репозитории

### Лимиты которых хватит с головой:
- ✅ Размер репозитория до 1 ГБ
- ✅ 100 ГБ трафика в месяц (это десятки тысяч посетителей в день)
- ✅ Бесплатный HTTPS, можно подключить свой домен
- ✅ Автоматическая сборка и публикация при каждом изменении
- ✅ Вся история изменений контента сохраняется (можно откатить старую версию гайда после патча)
- ✅ Можно дать доступ модераторам/редакторам через Pull Request

| Фича | Как сделать |

| Расписание стримов | Статический блок/табличка в Markdown или простой виджет |
| Темная/светлая тема | Из коробки у всех современных генераторов статики |
| Адаптив под телефоны/планшеты | Из коробки |
| Русский язык по умолчанию + при желании английская версия | i18n плагины из коробки |
| SEO (мета-теги, превью при отправке в ТГ/ВК) | Из коробки |
| RSS фид для подписчиков | Из коробки |
| Карта сайта для поисковых систем | Из коробки |

### 📚 Билды и гайды
| Фича | Как сделать |
|------|-------------|
| Каталог со всеми билдами | Каждый билд это отдельный Markdown файл в папке `/builds/`, на странице каталога карточки генерируются автоматически |
| Фильтры билдов (класс, сложность, бюджет, роль) | Чистый клиентский JS (можно использовать легковесный Alpine.js, или даже на ванилле), данные берутся из мета-данных билдов |
| Сортировка (актуальные сначала, для новичков сначала, бюджетные сначала) | Аналогично фильтрам, чистый JS |
| Карточка билда со всеми тегами (класс, скиллы, сложность, бюджет, версия лиги) | Все эти параметры пишутся в шапку Markdown файла (YAML frontmatter), оттуда автоматически подтягиваются в карточку и на страницу гайда |
| ⚡ Кнопка "Скопировать PoB" одним кликом | Встроенный браузерный API `navigator.clipboard`, ссылка хранится в мета-данных билда |
| Стадии прогрессии гайда (Акты → Ранние карты → Красные → Уберы) | Внутри Markdown статьи используй заголовки уровня 2 для каждого этапа, плагин для оглавления сделает автоматические якоря-ссылки |
| Вкладки/аккордеоны для разделов гайда (гемы/гир/дерево/плейстиль) | Готовые компоненты из UI библиотеки или простой JS, в Starlight/VitePress такие компоненты есть из коробки |
| Сравнительная таблица билдов с цветными оценками | Статическая таблица в Markdown или сгенерированная автоматически из данных всех билдов |
| Встроенный интерактивный пассивный древовидный просмотр | Iframe с [pob.cool](https://pob.cool/) или подключение открытого веб-PoB скрипта |
| ✅ Чеклист прогрессии по лиге (кап резов, лутфильтр и т.д.) | Чистый JS, состояние отмеченных галочек сохраняется в `localStorage` браузера пользователя (даже если он закроет сайт и вернётся — всё останется отмеченным) |
| Поиск по сайту и по билдам | Встроенный поиск на стороне клиента через **Pagefind** (умеет искать по русскому языку, работает без внешнего сервиса) или встроенный поиск у Starlight/Docusaurus |
| Актуальные цены уников подтягиваются прямо на страницу | Публичный API [poe.ninja](https://poe.ninja/api/data/currencyoverview?league=Crucible) у них открыт CORS для браузерных запросов, ценники подтягиваются фетчем при загрузке страницы |
| Прямые ссылки на трейд с готовыми фильтрами | Статические ссылки генерируются по шаблону `https://www.pathofexile.com/trade/search/...` |
| Пометка "Гайд устарел" кнопка | Можно использовать Giscus (комментарии) или простой mailto/ссылка на создание ишью в репозитории |
| Генерация красивых превью-картинок билда для шаринга в соцсети | Astro OpenGraph плагин генерирует их автоматически по заголовку/автору при сборке сайта |
| Экспорт в `.build` формат для PoE 2 встроенного планнера | Просто ссылка на скачивание файла лежащего в папке репозитория |

### 🎓 Фичи для новичков
| Фича | Как сделать |

| 🧪 Квиз/тест "Какой билд мне подходит?" | Чистый JS, логика теста полностью клиентская, результат выводится сразу, никакого сервера не нужно |

| Словарь терминов | Отдельная страница на Markdown + всплывашки при упоминании терминов в тексте гайдов |

### 💬 Комьюнити и интерактив
| Фича | Как сделать |
|------|-------------|
| Комментарии под каждым билдом/гайдом | **Giscus** — полностью бесплатная опенсорсная система которая использует **GitHub Discussions** в твоём репозитории. Пользователи логинятся через Гитхаб, все комментарии хранятся у тебя в репозитории, нет рекламы, нет сторонних сервисов, есть модерация. Альтернатива: Utterances на GitHub Issues |
| Форма "Подать PoB на разбор на стриме" | Форма через **Formspree** (бесплатный тариф хватит на тысячи отправок в месяц) или простая вставка Google Forms / Телеграм Вебхука который отправляет заявки сразу тебе в личку. Можно даже сделать чтобы форма автоматически создавала ишью в репозитории по шаблону через GitHub API |
| Зал славы (скриншоты зрителей на твоих билдах) | Markdown страница с галереей, добавляешь скриншоты в папку репозитория когда зрители присылают |
| ❤️ Избранное билды | Сохраняется в `localStorage` пользователя, аккаунт не нужен |
| Подписка на обновления о новых гайдах/старте лиги | Бесплатный сервис [follow.it](https://follow.it/) или RSS-канал который читает Телеграм-бот |
| Поделиться билдом в ТГ/ВК/Дискорд | Стандартные Web Share API + кнопки поделиться с ссылкой и картинкой превью |

## ⚠️ Что можно сделать, но с использованием внешних бесплатных сервисов

Этих фич нет из коробки для чисто статического сайта, но решаются бесплатно за 5 минут подключения стороннего сервиса:
1. 📧 **Почтовая рассылка о старте лиги** — бесплатный тариф Mailchimp/Beehiiv хватит на старт, или через тот же follow.it
2. 📝 **Визуальный редактор контента для стримерши** — подключи **Decap CMS** (ранее Netlify CMS) или **Tina CMS**. Они дают удобный интерфейс как в Ворде/Notion: пишешь гайд, вставляешь картинки, заполняешь поля для карточки билда, нажимаешь "Опубликовать" — изменения автоматически попадают в репозиторий и выкатываются на сайт. **НЕ НУЖНО ЗНАТЬ MARKDOWN ИЛИ КОД** чтобы добавлять новые гайды.
3. 📊 **Простая аналитика** — **Umami** (можно бесплатно хостить на том же GH Pages или Cloudflare Pages Analytics бесплатный), или Яндекс.Метрика/Google Analytics если не против трекинга.
4. 🔔 **Пуш-уведомления в браузер** — OneSignal бесплатный тариф.

## ❌ Что НЕЛЬЗЯ сделать на чистом GitHub Pages, и нужно ли это?

Честно говоря для такого сайта эти функции и не нужны, но перечислю для полноты картины:
1. ❌ Полноценная система пользовательских аккаунтов с регистрацией (не нужно: избранное/чеклисты и без аккаунтов работают в localStorage, комментарии через гитхаб)
2. ❌ Серверные вычисления/крафтовые симуляторы на бэкенде (можно если вынести на Cloudflare Workers, но для старта не обязательно, есть готовые внешние симуляторы крафта на которые можно сослаться)
3. ❌ Сложные калькуляторы ДПС которые обращаются к большой базе предметов — проще встроить готовый веб-PoB по ссылке
4. ❌ Динамический контент который меняется каждую минуту (но обновление цен раз в час/день через внешнее API нормально работает)

Все действительно нужные функции из твоего списка реализуются без проблем.

## 🛠️ Какой стек технологий выбрать? Лучший вариант для такого проекта

Я рекомендую **не писать всё с нуля на чистом HTML/CSS** — это убьёт кучу времени, и будет неудобно добавлять контент. Лучше взять готовый генератор статических сайтов, который даст 80% нужного функционала из коробки, и останется только подогнать дизайн под стиль стримерши.

### 🏆 Лучший вариант на 2026 год: **Astro + шаблон Starlight**
Это идеальный стек для гайдов/контентных сайтов:
- ✅ Собирает страницы в чистый статический HTML, грузятся за доли секунды
- ✅ **Starlight** это официальный шаблон для документации/гайдов от команды Astro, из коробки даёт:
  - Темная/светлая тема
  - Адаптивный дизайн под любые экраны
  - Оглавление статьи слева/справа
  - Хлебные крошки
  - Встроенный полнотекстовый поиск (в том числе по русскому языку)
  - Пагинация
  - i18n (многоязычность из коробки)
  - RSS фид
  - SEO мета-теги
  - Поддержка MDX (можно вставлять реакт/вью/ванила компоненты прямо в Markdown текст гайда — например калькулятор резистов, квиз и т.д.)
- ✅ Очень мало лишнего JS грузится в браузер пользователя
- ✅ Есть плагины буквально для всего что нам нужно: OG изображения, глоссарий, вкладки, аккордеоны, таблицы и т.д.
- ✅ Деплой на GitHub Pages одной кнопкой через готовый Action
- ✅ Можно легко кастомизировать абсолютно все части дизайна под фирменный стиль

### Достойные альтернативы если хочешь что-то попроще:
- **VitePress** — на Vue, очень быстрый, много готовых тем, для тех кто знаком с Vue
- **Hugo** — самый быстрый генератор (собирает 1000 страниц за 0.1 секунды), не нужен Node.js на компьютере, но чуть сложнее кастомизировать шаблоны
- **Jekyll** — поддерживается GitHub Pages из коробки без сборки через Actions, но он устарел, работает медленнее и гибкости сильно меньше

❌ Не рекомендую:
- Чистый HTML/CSS/JS — ад для поддержки и добавления новых гайдов
- Next.js static export — перебор для такого контентного сайта, тяжелее, больше сложностей
- WordPress/другие CMS с базой данных — не работают на GH Pages, нужен платный хостинг, постоянно требуют обновлений и взламываются
- Docusaurus — хороший, но слишком заточен под техническую документацию, сложнее кастомизировать дизайн под "живой" стримерский вид

## 📂 Как организовать контент — чтобы стримерша сама добавляла билды без программиста

Весь контент хранится в виде простых папок и файлов в репозитории:

```
poe-site/
├── public/
│   ├── loot-filters/        # Скачиваемые лутфильтры
│   ├── build-files/         # .build файлы для PoE2 планнера
│   └── images/
│       ├── builds/          # Скриншоты/обложки билдов
│       └── hall-of-fame/    # Скриншоты из зала славы
├── src/
│   ├── content/
│   │   ├── builds/          # ⬇️ ВОТ ТУТ ВСЕ БИЛДЫ
│   │   │   ├── rf-chieftain.md
│   │   │   ├── cold-dot-elementalist.md
│   │   │   └── toxic-rain-pathfinder.md
│   │   ├── guides/          # Общие гайды (для новичков, механики, крафт)
│   │   └── news/            # Посты про патчи, новости лиги
│   └── components/          # Интерактивные штуки: квиз, калькулятор, фильтры билдов
└── astro.config.mjs
```

Каждый файл билда (например `rf-chieftain.md`) выглядит вот так:

```markdown
---
# Эти поля заполняются при создании гайда, по ним автоматически строится карточка и фильтры
title: Righteous Fire Вождь
class: Marauder
ascendancy: Chieftain
skills: [Righteous Fire, Fire Trap,]
tags: [league-starter, mapping, bossing, ssf]
difficulty: 1
budget: starter
patch: "3.29"
league: "Curse of the Allflame"
lastUpdated: 2026-10-17
pob: "https://pastebin.com/xxxxx"
buildFile: "/build-files/rf-chieftain.build"
videoGuide: "https://youtube.com/..."
thumbnail: "/images/builds/rf-chief.jpg"
---

## Быстрый старт
Самый танковый билд для старта лиги, жмёшь две кнопки, подходит даже если ты первый раз играешь...

## Прогрессия
### Акты 1-3
Текст гайда для первых актов...

### Акты 4-10
...

## Гемы и линки
...
```

Стримерше достаточно просто **скопировать существующий файл билда**, поменять поля в шапке и написать текст гайда в Markdown. Это можно делать:
- Прямо через веб-интерфейс GitHub (не нужно ничего скачивать на компьютер)
- Через удобный визуальный редактор Decap CMS/Tina как в Ноушене
- В любом редакторе Markdown на компьютере

Когда она сохраняет изменения — через 1-2 минуты GitHub Actions автоматически пересобирает сайт и обновление уже в онлайне.

## 🚀 Пошаговый план как стартовать (можно сделать за один вечер):

### Этап 1 — Скелет сайта (1-2 часа)
1. Создай репозиторий на GitHub
2. Разверни стартовый шаблон Astro Starlight одной кнопкой "Use this template"
3. Настрой базовые параметры: название сайта, описание, цвета под фирменный стиль стримерши
4. Подключи деплой на GitHub Pages через готовый GitHub Action
5. Проверь что сайт открывается по адресу `nik.github.io/poe-site`

### Этап 2 — Базовая структура и дизайн (2-3 часа)
1. Настрой шапку: добавь ссылки на твич/ютуб/дискорд, иконку стримерши
2. Создай структуру страниц: Главная → Все билды → Новичкам → Гайды → Комьюнити → Обо мне
3. Настрой главную страницу: добавь приветствие, таймер до лиги, секцию с рекомендуемым стартовым билдом
4. Подключи тёмную тему по умолчанию
5. Добавь базовые стили под нужную палитру

### Этап 3 — Каталог билдов (3 часа)
1. Создай коллекцию контента для билдов, настроик считывание мета-полей из YAML
2. Сделай шаблон страницы отдельного билда (быстрый старт, кнопка PoB, стадии гайда, разделы)
3. Сделай страницу каталога с карточками
4. Добавь клиентские фильтры и сортировку по классу/сложности/бюджету

### Этап 4 — Добавляем интерактив (3-4 часа)
1. Подключи комментарии Giscus
2. Сделай компонент квиза "выбери билд"
3. Сделай чеклист прогресса с сохранением в localStorage
4. Добавь всплывающий глоссарий для терминов
5. Подключи встроенный Twitch плеер и индикатор онлайн-статуса
6. Добавь форму подачи PoB на разбор (через Formspree/телеграм вебхук)

### Этап 5 — Первый контент (сколько угодно времени)
1. Добавь 3-5 первых билдов (в первую очередь лигстартовый)
2. Добавь гайд для абсолютных новичков "Первый раз в PoE"
3. Добавь словарь терминов
4. Добавь лутфильтр и инструкцию по установке PoB

### Этап 6 — Опциональные доработки
- Подключи визуальный редактор Decap CMS для удобного добавления контента
- Добавь калькулятор резистов
- Подключи подтягивание цен с poe.ninja
- Добавь автоматический фетч последних видео с Ютуба
- Подключи аналитику
- Купи и подключи свой красивый домен (например `nickname-poe.ru` или что-то такое)
